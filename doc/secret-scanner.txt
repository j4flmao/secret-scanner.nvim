==============================================================================
1. INTRODUCTION                                    *secret-scanner-intro*

secret-scanner.nvim wraps gitleaks and surfaces findings as native Neovim
diagnostics — catching secrets in-buffer before they're ever committed.

==============================================================================
2. REQUIREMENTS                                  *secret-scanner-requirements*

- Neovim >= 0.10
- gitleaks >= 8.19 (https://github.com/gitleaks/gitleaks) installed and on
  PATH. Version 8.19 introduced the `git` subcommand that staged and hook
  scans rely on; older installs fall back to deprecated commands and scan
  working-tree files instead.

==============================================================================
3. SETUP                                              *secret-scanner-setup*

>
  require("secret-scanner").setup({
    -- see |secret-scanner-config| for options
  })
<

==============================================================================
4. COMMANDS                                      *secret-scanner-commands*

:SecretScannerScan              Scan the current buffer for secrets.
:SecretScannerScanStaged        Scan the staged diff for secrets.
:SecretScannerScanRepo          Scan the full repo history (opt-in). Findings
                                are filled into the quickfix list and `:copen`
                                is opened for navigation.
:SecretScannerScanProject       Scan the whole project working tree (opt-in) —
                                every file under the git root, tracked and
                                untracked alike. `gitleaks dir` honors
                                .gitignore, so dependency/build trees are
                                skipped. Findings go to the quickfix list.
:SecretScannerInstallHooks      Install git pre-commit (and opt-in pre-push)
:SecretScannerUninstallHooks    Uninstall git hooks, restoring any legacy hook.

5. CONFIGURATION                                  *secret-scanner-config*

Pass a table to `setup()`. Available keys:

  gitleaks_path            (string)  Path to gitleaks binary.
                                     Default: "gitleaks"
  scan_on_save             (boolean) Auto-scan on BufWritePost.
                                     Default: true
  scan_on_text_change      (boolean) Auto-scan on TextChanged / TextChangedI,
                                     debounced. Default: false
  debounce_ms              (integer) Debounce for save-triggered scans.
                                     Default: 300
  text_change_debounce_ms  (integer) Debounce for text-change scans.
                                     Default: 2000
  scan_on_commit           (boolean) Install/manage git hook.
                                     Default: true
  block_commit_on_finding  (boolean) Block commit when secrets found.
                                     Default: true
  pre_push_hook            (boolean) Also install a pre-push hook.
                                     Default: false
custom_config_path       (string?) Path to a custom gitleaks .toml.
                                      By default the rules EXTEND the built-in
                                      set via `[extend] useDefault = true`;
                                      set `override_default_rules = true` to
                                      fully replace them.
                                      Default: nil
  bundled_rules           (boolean) Layer the shipped extended ruleset (JWT,
                                      GitHub/GitLab tokens, Slack/Telegram/
                                      SendGrid keys, private keys, URL and
                                      ADO.NET connection strings, JSON/XML
                                      secret keys like "ClientSecret"/Jwt.Key,
                                      Java/JSP & servlet web.xml and
                                      context.xml credentials, YAML/.env
                                      KEY=value secrets, Vault tokens, .netrc,
                                      Kubernetes stringData, CI/CD pipeline
                                      variables, keyword-scoped
                                      high-entropy catch-all) over gitleaks'
                                      embedded defaults.
                                      Default: true
  override_default_rules   (boolean) When true, project-local config
                                      replaces the plugin defaults instead of
                                      merging over them.
                                      Default: false
  project_config_file      (string)  Name of the per-project config file.
                                      Default: ".secretscanner.lua"
  allowlist_file           (string)  Ignore file name.
                                      Default: ".secretscannerignore"
  severity                 (table)   `default` severity plus per-rule `rules`
                                      overrides, e.g. >
                                        severity = {
                                          rules = { ["noisy-rule"] =
                                            vim.diagnostic.severity.INFO },
                                        }
                                      <
  ui                       (table)   Display options:
                                       - virtual_text (boolean)
                                       - signs (boolean)
                                       - float_on_cursor_hold (boolean)
  timeout                  (integer) Max ms for a gitleaks scan.
                                      Default: 30000

For a statusline component:
>
  require("secret-scanner").statusline()
<
Returns "⚠ n secret(s)" or "" — wire it into lualine / mini.statusline.

==============================================================================
6. KEYMAPS                                        *secret-scanner-keymaps*

  <leader>ss   Scan the current buffer for secrets.
  <leader>sp   Scan the whole project working tree into the quickfix list.
  <leader>sa   Allowlist the finding under the cursor and rescan.

==============================================================================
7. ALLOWLISTING                                    *secret-scanner-allowlist*

Two ways to silent a false positive:

- Inline: append `secret-scanner:ignore` to the offending line, e.g.
    key = "AKIAIOSFODNN7EXAMPLE" -- secret-scanner:ignore
  The finding on that line is suppressed.

- Ignore file: a `.secretscannerignore` file in the repo root (configurable via
  `allowlist_file`). Each non-empty, non-`#` line is an entry:
>
    config.py:aws-access-key
    .env:github-pat:deadbeef
<
  The form is `<file>:<rule_id>` to allowlist every finding of that rule in
  that file, or `<file>:<rule_id>:<sha8>` (first 8 chars of the secret hash)
  to allowlist a single secret. Use <leader>sa to append entries.

8. PROJECT CONFIGURATION                  *secret-scanner-project-config*

Place a `.secretscanner.lua` in the repo root (configurable via
`project_config_file`) to set team-mandated options per project:
>
  return {
    scan_on_text_change = true,
    severity = { rules = { ["noisy-rule"] = vim.diagnostic.severity.INFO } },
  }
<
Values merge over the user's `setup()` config, so team policy wins. Changes are
picked up automatically (cache is invalidated on file mtime/size change). With
`override_default_rules = true`, project values replace the plugin defaults and
the user config is ignored.

CUSTOM RULESETS AND MERGE STRATEGY                        *secret-scanner-merging*

`custom_config_path` points at a gitleaks .toml ruleset. How that ruleset is
combined with the effective rules is controlled by `override_default_rules`:

- extend (default): the custom rules are layered on top of the built-in rules,
  which in turn are layered on top of the bundled extended ruleset when
  `bundled_rules = true` (the default). gitleaks supports this natively via
  `[extend] useDefault = true`. New rule IDs are added; a rule whose `id`
  matches a built-in one overrides it per-field (`Description`, `Entropy`,
  `SecretGroup`, `Regex`, `Path`) while its tags, keywords and allowlists are
  appended.
- replace: with `override_default_rules = true` the custom config is passed
  through verbatim — every other rule is dropped. Use this only for a
  deliberately locked-down ruleset.

In extend mode the plugin materializes a derived config under
`stdpath("cache")/secret-scanner` so gitleaks always reads a single, plain TOML
file; your committed ruleset is never modified. If your custom file already
contains its own `[extend]` section, the plugin passes it through untouched.
Installed git hooks bake the same resolved path and fall back to the original
file if the cache was cleared, so hooks never silently lose the default rules.

Inspect the shipped examples for ready-to-adapt rulesets and allowlists:

  examples/spring-boot/
  examples/go/

Malformed TOML or an unreadable path is reported once via `:checkhealth` and as
an error notification on the first scan — never a silent misconfiguration.
